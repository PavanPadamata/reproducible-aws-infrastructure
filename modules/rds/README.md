# rds module

A private, encrypted PostgreSQL (or MySQL) database whose password nobody
types.

| Setting | Value |
|---------|-------|
| Network | Subnet group of the isolated data subnets; `publicly_accessible = false` |
| Inbound | Database port only, from named security groups. No CIDR ranges |
| Outbound | None |
| Storage | gp3, always encrypted |
| Password | Generated by RDS, kept in Secrets Manager (`manage_master_user_password`) |
| Protection | Deletion protection and a final snapshot, both on by default |

## Usage

```hcl
module "db" {
  source = "../../modules/rds"

  name       = "myproj-dev-db"
  vpc_id     = module.vpc.vpc_id
  subnet_ids = values(module.vpc.data_subnet_ids)

  allowed_security_group_ids = [module.app.security_group_id]
}
```

The caller also needs an outbound rule on the application's security group
for the database port, because the module cannot edit a group it does not
own. `envs/dev` shows this.

## Where the password is

There is **no password variable.** RDS generates the master password and
stores it in a Secrets Manager secret; the module outputs only the secret's
ARN. To read it:

```bash
aws secretsmanager get-secret-value --secret-id <master_user_secret_arn> \
  --query SecretString --output text
```

Because RDS generates the password, it is never an input to Terraform: it is
not in any `.tf` file, variable or `tfvars` file. State still holds other
sensitive attributes and deserves protection (ADR 0003, ADR 0005).

## Design notes

- **Two subnets are required even for one instance.** RDS needs a subnet
  group that spans at least two Availability Zones, so a failover target can
  exist. The module rejects a shorter list at plan time.
- **Deletion protection is on by default,** so `terraform destroy` fails on
  a database. A throwaway environment must set `deletion_protection = false`
  and, if it does not want a snapshot, `skip_final_snapshot = true`. Both are
  explicit choices, visible in the calling code.
- **Single-AZ by default.** `multi_az = true` adds an automatic-failover
  standby and doubles the instance cost.
- **`engine_version` follows a major version,** so AWS applies minor
  upgrades. Pin a full version for a stricter, more reproducible setup.
- **The module does not choose the subnets.** Passing public subnets would
  still create a private database (`publicly_accessible = false`), but
  isolation is strongest in subnets with no internet route.

## Cost drivers

Instance hours, storage, backups beyond the free allocation, `multi_az`,
and any CloudWatch log exports. No prices are quoted here because none have
been measured.

## Tests

```bash
cd modules/rds
terraform init -backend=false
terraform test
```

The tests use a mock provider, so they need no AWS credentials and create
nothing.
